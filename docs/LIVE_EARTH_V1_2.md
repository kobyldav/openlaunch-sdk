# OpenLaunch v1.2.0 — Satellite map layers, NRT data and official live streams

**Status:** development on `feature/live-earth-layers-v1.2.0`. Backwards-compatible with v1.1. Never assume `@openlaunch/*` packages are available on public npm until explicitly published.

## Architectural contract: the site is a renderer, SDK owns integrations

Your web app does **not** need direct access to NASA/EUMETSAT/Copernicus APIs. It asks `@openlaunch/earth` or the umbrella `OpenLaunch().earth.maps` for layer metadata, authenticated provider queries, tile descriptors, hotspots, atmospheric imagery and official stream metadata. MapLibRE/Leaflet displays the output. **Actual upstream pixels/video originate from the official space agencies**, not from synthetic assets generated by this SDK.

```ts
import { SpaceMapClient, bbox } from "@openlaunch/earth";

const maps = new SpaceMapClient({
  // On the backend only; do not leak private NASA FIRMS MAP_KEY to browser:
  firmsMapKey: process.env.NASA_FIRMS_MAP_KEY,
  // Sentinel-5P Process API needs Copernicus auth:
  copernicus: { clientId: process.env.CDSE_CLIENT_ID, clientSecret: process.env.CDSE_CLIENT_SECRET },
});

const layers = maps.layers(); // 18 descriptors, 4 groups, consistent source/time/status
const optical = maps.layers("observations");
const analytical = maps.layers("analyses");
const archives = maps.layers("terrain-history");
const video = maps.layers("live-video");
```

### Public layer groups

| Group | Exposed IDs | SDK service |
| --- | --- | --- |
| observations | sentinel2-optical, sentinel1-radar, landsat-temperature | Copernicus / Planetary Computer STAC |
| observations | meteosat-weather | Live EUMETView WMS capabilities and map requests |
| observations | nasa-modis-terra, nasa-viirs-snpp | NASA GIBS dated WMTS imagery |
| analyses | vegetation-ndvi, water-ndwi, moisture-ndmi, burn-scar-nbr | Raster-derived scientific index grids: `ndviRaster`, `ndwiRaster`, `ndmiRaster`, `nbrRaster` |
| analyses | atmosphere-no2, atmosphere-so2 | Sentinel-5P Level 2 Copernicus Process API |
| analyses | fires-viirs | NASA FIRMS authenticated hotspot API |
| terrain-history | dem-terrain, time-comparison, archive-scenes | DEM/STAC plus COG raster analysis |
| live-video | iss-video, meteosat-video | Official NASA/EUMETSAT third-party YouTube embeds |

Layer metadata intentionally sets `observationTime:null`, `liveVerified:false`, `resolutionMetres:null` until actual acquisition metadata is retrieved. Never use the server's `Date.now()` as a capture time.

## NASA GIBS: MODIS/VIIRS daily imagery

```ts
const descriptor = maps.nasaDailyTiles("MODIS_Terra_CorrectedReflectance_TrueColor", "2026-10-12");
console.log(descriptor.urlTemplate);
// https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/.../default/2026-10-12/GoogleMapsCompatible_Level9/{z}/{y}/{x}.jpg

// Download an actual tile via bounded HTTPS; validates provider image MIME and range:
const tile = await maps.gibs.fetchTile(
  "MODIS_Terra_CorrectedReflectance_TrueColor", "2026-10-12", 6, 34, 22
);
```

Leaflet/MapLibre consume `urlTemplate` (max zoom 9) as a dated XYZ layer. `maps.nasaDailyTimeline(layer,from,to)` yields up to 31 sequential UTC-day descriptors, each with availability explicitly unverified. Historical playback is implemented by requesting a different UTC calendar date; the SDK does **not** claim every requested day has an available tile. NASA GIBS publishes global map-tiles, not high-resolution village-level Sentinel images.

Official docs: https://nasa-gibs.github.io/gibs-api-docs/access-basics/

## Meteosat: near-real-time clouds/weather over Czechia

EUMETSAT EUMETView supports WMS. Because layer names change, **read live GetCapabilities first**:

```ts
const available = await maps.meteosatCapabilities();
console.log(available.layers); // only identifiers actually advertised by EUMETView
const chosen = available.layers.find(l => l.id.includes("mtg"));
if (!chosen) throw new Error("Required Meteosat WMS layer unavailable");

const image = await maps.meteosat.fetchMap({
  layer: chosen.id,
  bounds3857: [1300000, 6200000, 1900000, 7000000],
  width: 512, height: 512,
});
// Image bytes are received from real EUMETView WMS; caller georeferences via the returned descriptor.
```

SDK handles the WMS 1.1.1 URL, EPSG:3857 projected bounds, image sizes, timeout, response MIME. It does **not** fabricate timestamps or infer an imaging frame from URL time. For displayed "latest" status, inspect provider time dimensions / metadata upstream and publish a `checkedAt` value, and distinguish that from the **observed** timestamp. A server default WMS layer may be from an earlier hour.

Official EUMETSAT WMS: https://view.eumetsat.int/geoserver/wms

### Official Meteosat Europe video stream

```ts
const video = maps.videoStream("meteosat-europe-live");
console.log(video.embedUrl, video.watchUrl, video.officialSourceUrl);
```

EUMETSAT reported in May 2026 that Meteosat-12 Europe/Africa YouTube composites update roughly every **10 minutes** with about **30 minutes publication delay**. It is near-real-time animation, not a zero-latency video feed or a georeferenced raster that can be directly overlaid on arbitrary map coordinates. Upstream live availability is unverified by this static descriptor.

Official reference: https://www.eumetsat.int/new-satellites-eye-views-europe-and-africa-streaming-online

## Sentinel-5P: NO₂ and atmosphere

```ts
// Requires Copernicus Sentinel Hub OAuth credentials (backend).
const response = await maps.airQuality({
  area: bbox(12,48,19,52),
  from: "2026-10-13T00:00:00Z",
  to: "2026-10-13T23:00:00Z",
  species: "NO2",
  minQa: 75,
  timeliness: "NRTI",
  width: 512,
  height: 512,
});
console.log(response.contentType, response.unit, response.observedAt); // image/png, mol/m², null
```

The `area` is a real WGS84 `bbox(...)` AreaOfInterest for the Czech Republic. Supported `species`: NO2, SO2, CO, O3, CH4, HCHO, AER_AI_340_380. `Sentinel5pClient.scenes()` also queries the Copernicus STAC catalogue for product metadata; default NO2 collection: `sentinel-5p-l2-no2-offl`. Catalog search and Process API are **different product interfaces**.

- Output PNG is *colorized* with a `dataMask`, not a high-fidelity float32 science raster.
- Column densities (mol/m²) are **not** ground-level air concentrations in µg/m³.
- Rendered pixels may cover mixed acquisition times; `observedAt:null` until actual scene provenance can be established.
- Do not confuse a `minQa` numerical threshold with an absolute quality guarantee.
- Sentinel Hub may impose resolution and quota limits.

Official docs: https://documentation.dataspace.copernicus.eu/APIs/SentinelHub/Data/S5PL2.html

## Active fires: NASA FIRMS

```ts
const map = new SpaceMapClient({ firmsMapKey: process.env.NASA_FIRMS_MAP_KEY });
const points = await map.activeFires([12,48,19,52], {
  source: "VIIRS_NOAA21_NRT",
  days: 1,
});
console.log(points.observations.map(p=>({
  lon: p.longitude, lat:p.latitude, acquiredAt:p.acquiredAt,
  radiativePowerMW:p.frpMegawatts,
})));
```

Each detection includes UTC acquisition timestamp from the source `acq_date` and `acq_time`, source satellite, confidence and optional FRP. Thermal anomalies are **points**, not verified wildfire polygons. FIRMS needs a free MAP_KEY. Keep the key in **Cloudflare Worker/backend secrets**, never in public JavaScript, URLs to a browser or open logs. Cache aggressively and respect transaction limits.

Default is **VIIRS NOAA-21**, because NASA FIRMS warns that Suomi-NPP data delivery is scheduled to cease November 1, 2026. NOAA-20 and MODIS remain selectable. The provider service may change independently.

Official docs: https://firms.modaps.eosdis.nasa.gov/api/area/

## NASA ISS stream

```ts
const stream = maps.videoStream("iss-earth-live");
// Render stream.embedUrl in your site's opt-in sandboxed iframe,
// or offer stream.watchUrl as an external watch link.
```

`SpaceVideoClient` contains verified official NASA/EUMETSAT channel/watch links, embedding hints and honest `availability:"not-checked"`. It does **not** download, retransmit, rehost, decode or claim ownership of live video. NASA notes that prerecorded Earth-view loops may be shown during camera downtime, and an ISS camera is **not continuously over the Czech Republic**. An embed may stop working if the broadcaster ends or replaces the video.

Official NASA page: https://www.nasa.gov/live/

## Time and availability contract

```ts
const status = maps.sceneFreshness(actualStacItem, new Date(), 6 * 60);
console.log(status.observationTime, status.ageMinutes, status.freshness);
// Always check 'unknown' and 'stale'; never label it as a verified LIVE feed.
```

UI status recommendations:
- **LIVE VIDEO:** only the external-stream type, showing provider attribution; dynamic uptime not verified.
- **Near realtime:** Meteosat WMS, Sentinel-5P NRTI, FIRMS; include latency and data timestamp when verified.
- **Daily / historical:** NASA GIBS UTC-day mosaics, Landsat and Sentinel STAC scenes.
- **Derived on demand:** NDVI, NDWI, NDMI, NBR, change maps, DEM meshes; computed from real aligned raster bands.

## Limitations and next engineering milestones

- Product-integrated Sentinel-5P Processing currently provides PNG; **numeric GeoTIFF, qa masks and physical units per pixel** need separately validated multiband TIFF handling.
- EUMETView WMS discovery lists advertised layer names but does not parse all nested capability metadata/time axes. **Automatic hourly movie animation and provider-confirmed timestamps** are a next stage.
- NASA GIBS layer presets/zoom and availability should be cross-checked against current WMTS Capabilities for a production UI.
- Browser support depends on upstream CORS and embedding policy. Use a **secure backend proxy** if necessary, with explicit upstream host allowlist, transfer budgets, caching and limits.
- Never expose OAuth client secret, FIRMS MAP_KEY or Planetary Computer asset signing tokens in the frontend.
- Raster tiles and video streams are distinct products; map pixels must be georeferenced and authorized before overlay.
- Live upstream health/authenticated provider access was not asserted by offline CI. Use opt-in live integration checks with your credentials and quotas.
